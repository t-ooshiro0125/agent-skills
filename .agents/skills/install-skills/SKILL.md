# Install Skills

## 目的と対象

このリポジトリの配布用 `skills/<skill-name>/` を、登録先の直下に個別リンクまたは実ファイルのコピーとして配置する。全登録と選択登録に対応し、`.agents/skills/` 内のリポジトリ専用スキル（`install-skills` を含む）は登録しない。登録・同期・切替・削除と Git 除外設定の操作には、付属の [scripts/install.py](../../../scripts/install.py) を使う。

登録・同期・移行・削除を依頼された場合に実行する。導入方法の相談だけの場合は説明にとどめる。登録依頼に、取得元リポジトリの取得・更新、スキルの編集、別の既存項目の置き換え、指定外の登録の削除は含めない。利用先の規約と実行環境の書き込み権限に従う。

## 登録手順

登録元・登録先・対象が指定済みなら聞き直さず、同じ会話で指定されたエージェントと適用範囲も引き継ぐ。

1. 指定された `SKILL.md` または読み込んだこのスキルの実体パスから、登録元リポジトリを特定する。現在の作業ディレクトリを登録元と決めつけない。
2. 実体の `SKILL.md` があるディレクトリから3階層上をリポジトリのルートとし、`scripts/install.py` と `skills/` を確認する。付属スクリプトがない場合は、取得済みのリポジトリのパスを確認する。
3. 登録先が未指定の場合は、Codex 向けか Claude Code 向けか、ユーザー全体かプロジェクト単位かを確認する。プロジェクトのパスが不明なら併せて確認し、登録先が確定するまで実行しない。配置先は次の表に従う。

   | エージェント | ユーザー全体       | プロジェクト単位           |
   | ------------ | ------------------ | -------------------------- |
   | Codex        | `~/.agents/skills` | `<project>/.agents/skills` |
   | Claude Code  | `~/.claude/skills` | `<project>/.claude/skills` |

4. 指定された方式を引き継ぎ、未指定の場合は既定の個別リンク方式を使う。コピー方式では、取得元が見えない環境でも使える実ファイルを配置する。取得元の Git 管理対象ファイルの作業ツリー内容が対象となる。新規ファイルは `git add` 後、コミット前でも対象となる。登録だけの依頼で未追跡ファイルを自動でステージしない。
5. 登録先を必須引数としてスクリプトを実行する。`skill_repo` と `skill_install_dir` は確認した絶対パスとする。対象の指定がなければ全登録し、指定があれば登録先に続けてスキル名を渡す。

   ```sh
   python3 "$skill_repo/scripts/install.py" "$skill_install_dir"
   ```

   選択登録の例：

   ```sh
   python3 "$skill_repo/scripts/install.py" "$skill_install_dir" edit-prose review-workflow
   ```

   コピーの登録・再同期の例：

   ```sh
   python3 "$skill_repo/scripts/install.py" "$skill_install_dir" --mode copy
   ```

Codex 向けに `~/.codex/skills` への重複登録を要求しない。Claude Code が `.agents/skills` を自動探索することは前提にしない。

## 選択・移行・削除の扱い

- 選択登録では依存スキルを自動追加しない。リンク方式では、相対参照をリンクの実体である取得元の `skills/<skill-name>/` を基準に解決する。直接呼び出す依存スキルは名前を指定して追加登録する。参照を保つため、取得元リポジトリは移動・削除しない。
- コピー方式では、依存先も管理済みコピーとして登録先に必要となる。依存不足のエラーでは、表示された名前を追加指定する方法を案内し、依頼範囲に含まれない依存スキルを勝手に登録しない。取得元を更新する操作と、コピーを同期する操作は区別する。スキル内のファイル削除・改名は同期するが、取得元から消えたスキル全体は残し、不要なら明示削除するよう案内する。
- 同じ登録元を指す個別リンクは再利用する。通常の登録では、指定外の既存登録とその Git 除外記録を残す。
- リンク方式で同じ登録元の `skills/` を指す、Git 管理対象でない一括リンクがあれば、利用範囲を維持するため全スキルを個別登録してから一括リンクを削除する。名前を指定していても移行時は全登録する。競合する項目や Git 管理対象の一括リンクがあれば停止する。別の既存項目になった一括リンクは変更しない。コピー方式では旧一括リンクがあれば変更前に停止するため、先に通常のリンク登録で個別リンクへ移行する。
- コピー方式への切替を依頼された場合は、同じ取得元の個別リンクから `--mode copy` で直接切り替える。取得元の本体は変更しない。コピーからリンクへ戻す場合は、コピーの明示削除後に通常登録する。リンク登録だけで既存コピーを置き換えない。
- 削除を依頼された場合だけ、明示された名前を `--remove` に渡す。一括リンクがあれば先に通常の登録で移行する。対象を減らす依頼で削除する名前が不明なら確認し、推測で削除しない。

  ```sh
  python3 "$skill_repo/scripts/install.py" "$skill_install_dir" --remove review-workflow
  ```

- リンク方式で削除できるのは同じ登録元の同名スキルを指し、Git 管理対象でないリンクだけ。別の既存項目や Git 管理対象が指定に含まれれば、リンクを削除せず停止する。取得元のスキル本体は削除しない。

- コピーの削除を依頼された場合は、`--mode copy --remove` を使う。管理情報と独自変更の確認に失敗した対象を、手動削除や強制上書きで処理しない。

  ```sh
  python3 "$skill_repo/scripts/install.py" "$skill_install_dir" --mode copy --remove worktree-create
  ```

Git リポジトリ内では、登録リンク・コピー・コピーの管理情報を `info/exclude` の専用範囲で除外する。リンク方式で対象にコピーの管理情報が残っている場合は、除外記録を維持して停止する。それ以外では、移行・削除したリンクや、リンク方式で今回の対象が別の項目・Git 管理対象になった場合の古い記録は取り除く。指定外のスキル、ほかの登録先、専用範囲外の記録は維持する。worktree では共通の除外ファイルを使い、Git リポジトリ外では除外設定を行わない。

## 完了確認と出力

終了コード、作成・再利用・同期・削除した項目、登録方式、リンクの参照先、一括リンクの移行、更新した除外ファイルを確認して報告する。

コピー方式では、登録先の `.agent-skills-copy/` にスキルごとの管理情報と復旧情報を保存する。事前に独自変更・管理情報の不備・依存不足・コピー対象のシンボリックリンク・既存項目や Git 管理対象との衝突を検出した場合、コマンド全体を変更前に停止する。自動マージや強制上書きは行わない。

実行途中の失敗では、リンク方式は既存どおり完了済みの変更を残す。コピー方式はスクリプトがスキル単位でコピーと管理情報を復旧し、完了済みの別スキルは残す。どちらも対象・理由・実際に残った状態を確認して報告する。コピーの復旧待ち情報があれば、原因解消後に同じ対象のコマンドを再実行する。退避内容・管理情報を手動で削除しない。

ファイルシステム上の登録確認と、エージェント上の認識確認を区別する。Codex では `/skills` または `$`、Claude Code では `/` の候補で確認し、表示されなければ再起動することを案内する。リンク方式の既存内容は取得元の変更で反映される。コピー方式の同期と、どちらの方式でも新規スキルの追加登録には、インストーラーの再実行が必要であることを伝える。手動編集・`git pull` だけではコピーは同期されない。

導入・移行・削除・検証の詳細は [利用ガイド](../../../docs/usage/install-skills.md) を参照する。
