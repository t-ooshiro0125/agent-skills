# Install Skills

## 目的と対象

このリポジトリの配布用 `skills/<skill-name>/` へのシンボリックリンクを登録先の直下に作成する。全登録と選択登録に対応し、`.agents/skills/` 内のリポジトリ専用スキル（`install-skills` を含む）は登録しない。リンクと Git 除外設定の操作には、付属の [scripts/install.py](../../../scripts/install.py) を使う。

登録・移行・削除を依頼された場合に実行する。導入方法の相談だけの場合は説明にとどめる。登録依頼に、取得元リポジトリの取得・更新、スキルの編集、別の既存項目の置き換え、指定外リンクの削除は含めない。利用先の規約と実行環境の書き込み権限に従う。

## 登録手順

登録元・登録先・対象が指定済みなら聞き直さず、同じ会話で指定されたエージェントと適用範囲も引き継ぐ。

1. 指定された `SKILL.md` または読み込んだこのスキルの実体パスから、登録元リポジトリを特定する。現在の作業ディレクトリを登録元と決めつけない。
2. 実体の `SKILL.md` があるディレクトリから3階層上をリポジトリのルートとし、`scripts/install.py` と `skills/` を確認する。付属スクリプトがない場合は、取得済みのリポジトリのパスを確認する。
3. 登録先が未指定の場合は、Codex 向けか Claude Code 向けか、ユーザー全体かプロジェクト単位かを確認する。プロジェクトのパスが不明なら併せて確認し、登録先が確定するまで実行しない。配置先は次の表に従う。

   | エージェント | ユーザー全体       | プロジェクト単位           |
   | ------------ | ------------------ | -------------------------- |
   | Codex        | `~/.agents/skills` | `<project>/.agents/skills` |
   | Claude Code  | `~/.claude/skills` | `<project>/.claude/skills` |

4. 登録先を必須引数としてスクリプトを実行する。`skill_repo` と `skill_install_dir` は確認した絶対パスとする。対象の指定がなければ全登録し、指定があれば登録先に続けてスキル名を渡す。

   ```sh
   python3 "$skill_repo/scripts/install.py" "$skill_install_dir"
   ```

   選択登録の例：

   ```sh
   python3 "$skill_repo/scripts/install.py" "$skill_install_dir" edit-prose review-workflow
   ```

Codex 向けに `~/.codex/skills` への重複登録を要求しない。Claude Code が `.agents/skills` を自動探索することは前提にしない。

## 選択・移行・削除の扱い

- 選択登録では依存スキルを追加登録しない。相対参照は、リンクの実体である取得元の `skills/<skill-name>/` を基準に解決する。直接呼び出す依存スキルは名前を指定して追加登録する。参照を保つため、取得元リポジトリは移動・削除しない。
- 同じ登録元を指す個別リンクは再利用する。通常の登録では、指定外の既存リンクとその Git 除外記録を残す。
- 同じ登録元の `skills/` を指す、Git 管理対象でない一括リンクがあれば、利用範囲を維持するため全スキルを個別登録してから一括リンクを削除する。名前を指定していても移行時は全登録する。競合する項目や Git 管理対象の一括リンクがあれば停止する。別の既存項目になった一括リンクは変更しない。
- 削除を依頼された場合だけ、明示された名前を `--remove` に渡す。一括リンクがあれば先に通常の登録で移行する。対象を減らす依頼で削除する名前が不明なら確認し、推測で削除しない。

  ```sh
  python3 "$skill_repo/scripts/install.py" "$skill_install_dir" --remove review-workflow
  ```

- 削除できるのは同じ登録元の同名スキルを指し、Git 管理対象でないリンクだけ。別の既存項目や Git 管理対象が指定に含まれれば、リンクを削除せず停止する。取得元のスキル本体は削除しない。

Git リポジトリ内では、登録リンクを `info/exclude` の専用範囲で除外する。移行・削除したリンクや、今回の対象で別の項目・Git 管理対象になったリンクの古い記録は取り除く。指定外のスキル、ほかの登録先、専用範囲外の記録は維持する。worktree では共通の除外ファイルを使い、Git リポジトリ外では除外設定を行わない。

## 完了確認と出力

終了コード、作成・再利用・削除したリンクと参照先、一括リンクの移行、更新した除外ファイルを確認して報告する。失敗時は途中までの変更も確認して報告し、自動では巻き戻さない。

ファイルシステム上の登録確認と、エージェント上の認識確認を区別する。Codex では `/skills` または `$`、Claude Code では `/` の候補で確認し、表示されなければ再起動することを案内する。登録済みスキルの内容は取得元の更新で反映されるが、新しいスキルの追加登録にはインストーラーの再実行が必要であることを伝える。

導入・移行・削除・検証の詳細は [利用ガイド](../../../docs/usage/install-skills.md) を参照する。
