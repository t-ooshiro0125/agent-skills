# Install Skills

## 目的と対象

登録先に `agent-skills` というシンボリックリンクを一つ作成し、このリポジトリの配布用 `skills/` 全体を参照させる。新しいスキルも再登録せず反映され、各スキルは個別に呼び出せる。`.agents/skills/` 内のリポジトリ専用スキルは、`install-skills` 自体も含めて登録対象にしない。リンク作成は、リポジトリ付属の [scripts/install.py](../../../scripts/install.py) に任せる。

登録を依頼された場合に実行する。導入方法の相談だけの場合は説明までにとどめる。リポジトリの取得・更新、スキルの編集、別の既存項目の置き換えは登録依頼に含めない。

## 登録手順

登録元・登録先が指定済みなら聞き直さず、同じ会話で指定された利用範囲や登録先も引き継ぐ。利用先の規約と実行環境の書き込み権限に従い、次の順に進める。

1. ユーザーが指定した `SKILL.md` のパス、または読み込んだこのスキルのパスから、登録元のリポジトリを特定する。リンク経由で読み込んだ場合は実体のパスをたどる。現在の作業ディレクトリを登録元と決めつけない。
2. 実体の `SKILL.md` があるディレクトリから3階層上をリポジトリのルートとし、`scripts/install.py` と `skills/` があることを確認する。このスキルのフォルダだけがコピーされ、付属スクリプトがない場合は、取得済みのリポジトリのパスを確認する。
3. 登録先が未指定の場合は、ユーザー用の `~/.agents/skills/` に共通登録するか、特定のプロジェクトの `.agents/skills/` に登録するかをユーザーに確認する。回答を受け取るまで登録処理を実行しない。プロジェクト専用を選び、対象プロジェクトが不明な場合は、そのパスも確認する。
4. 登録元と登録先を確定したら、対話式ではない登録スクリプトに登録先を必須引数として渡し、次のコマンドを実行する。登録スクリプトは Python 3 の標準ライブラリと Git を使用する。`skill_repo` と `skill_install_dir` は、確認したリポジトリと登録先の絶対パスとする。

   ```sh
   python3 "$skill_repo/scripts/install.py" "$skill_install_dir"
   ```

## 登録スクリプトの動作と失敗時の対応

- 同じ登録元を指す一括リンクは再利用する。別の既存項目・Git 管理対象が同名で存在する場合は、上書きせず停止する。
- 旧個別リンクは、同じ登録元の同名スキルを指し、Git 管理対象でないものだけ、一括リンク作成後にスクリプトが削除する。別の既存項目と Git 管理対象は残す。
- Git リポジトリ内では、一括リンクだけを `info/exclude` の専用範囲で除外する。現在の登録先の旧個別スキルの記録と、別の項目や Git 管理対象になった一括リンクの古い記録は取り除く。ほかの登録先の記録と専用範囲外のルールは維持する。worktree では共通の除外ファイルを使い、Git リポジトリ外では除外設定を行わない。

失敗時は、途中までに作成されたリンク、更新された除外設定、移行済みの個別リンクの状態を確認して報告する。自動では巻き戻さない。

## 完了確認と出力

終了コード、作成・再利用した一括リンクと参照先、移行した旧個別リンク、更新した除外ファイルを確認して簡潔に報告する。別の既存項目や Git 管理対象のため移行しなかった項目、失敗した処理と途中までの状態があれば併せて示す。

ファイルシステム上の登録確認と、Codex 上での読み込み確認を区別する。Codex CLI・IDE 拡張では `/skills` または `$` で登録したスキルを確認できることを案内し、追加が表示されない場合は Codex の再起動を案内する。
