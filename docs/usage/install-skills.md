# install-skills

このリポジトリの配布用 `skills/<skill-name>/` を、登録先の直下にスキルごとに配置します。全登録と名前による選択登録、個別リンク方式とコピー方式に対応します。`.agents/skills/` 内のリポジトリ専用スキル（`install-skills` を含む）は配布しません。

| 方式              | 適した利用場面                                    | 更新方法                                               |
| ----------------- | ------------------------------------------------- | ------------------------------------------------------ |
| `symlink`（既定） | 取得元のパスを参照でき、編集をすぐ反映したい場合  | 既存スキルの内容はリンク経由で反映。新規スキルは再登録 |
| `copy`            | Dev Containers など、登録先だけをマウントする場合 | 取得元の内容を変更した後、`--mode copy` で再実行       |

## コマンドで導入する

Git・Python 3 が使える macOS・Linux の環境で、取得したリポジトリのルートから実行します。エージェントの起動は不要です。登録先は必須引数で、利用するエージェントと適用範囲に応じて指定します。`/path/to/project` は対象プロジェクトの絶対パスに置き換えてください。

| エージェント | 適用範囲         | 全スキルの登録コマンド                                         |
| ------------ | ---------------- | -------------------------------------------------------------- |
| Codex        | ユーザー全体     | `python3 scripts/install.py "$HOME/.agents/skills"`            |
| Codex        | プロジェクト単位 | `python3 scripts/install.py "/path/to/project/.agents/skills"` |
| Claude Code  | ユーザー全体     | `python3 scripts/install.py "$HOME/.claude/skills"`            |
| Claude Code  | プロジェクト単位 | `python3 scripts/install.py "/path/to/project/.claude/skills"` |

Codex 向けに `~/.codex/skills` へ重複登録する必要はありません。Claude Code 向けには `.claude/skills` を指定し、`.agents/skills` の自動探索には依存しません。

一部だけを登録する場合は、登録先に続けてスキルのディレクトリ名を指定します。

```sh
python3 scripts/install.py "$HOME/.agents/skills" edit-prose review-workflow
```

指定しない場合は全スキルを登録します。存在しない名前や配布対象外の名前は、リンクや Git 除外設定を書き換える前に検出します。同名のリンクが同じ登録元を指していれば再利用し、別の既存項目や Git 管理対象があれば上書きせず停止します。

登録対象の選択と個別呼び出しは別の操作です。全スキルを登録していても、Codex では `$edit-prose`、Claude Code では `/edit-prose` のように名前を指定して呼び出せます。

### コピー方式で配置する

同じ配置先のコマンドに `--mode copy` を付けます。選択登録ではスキル名を登録先に続けて指定できます。

```sh
python3 scripts/install.py "$HOME/.agents/skills" --mode copy
python3 scripts/install.py "/path/to/project/.claude/skills" worktree-create --mode copy
```

`SKILL.md`・参照資料・補助スクリプト・テストを含め、Git 管理対象ファイルの作業ツリー上の内容を配置します。未コミットの変更も反映します。新規ファイルは `git add` 後に対象となり、コミットは不要です。未追跡のキャッシュや一時ファイルはコピーしません。コピー対象内のシンボリックリンクやサブモジュール、競合中のファイルは、変更前に停止して該当パスを案内します。

取得元が見えない環境でも配置したスキルを利用できます。同期・管理の操作は、登録時と同じ実パスの取得元リポジトリから実行してください。管理情報に記録する取得元のパスは所有判定に使い、スキルの利用時にそのパスへアクセスする必要はありません。

### 依存スキル

どちらの方式でも、選択登録で依存スキルを自動追加しません。リンク方式では、相対リンクをリンクの実体である取得元の `skills/<skill-name>/` を基準に解決してください。例えば `review-workflow` だけを登録しても、参照先の `../review/SKILL.md` などは取得元リポジトリに残っているため読み取れます。

依存スキルも名前で直接呼び出したい場合は、その名前を追加指定して登録してください。取得元のスキルを選別して削除したり、リポジトリを移動・削除したりすると参照が切れるため、そのまま残します。

コピー方式では、Markdown のリンクと `../...` 形式の相対パスから依存参照を確認します。依存先も同じ取得元の管理済みコピーとして配置するか、今回のコマンドに明示して含めてください。依存先がリンクだけの場合や未登録の場合は、コマンド全体を変更前に停止し、追加指定する名前を案内します。案内された名前も含めて再実行してください。参照資料が未追跡の場合も、先に `git add` が必要です。

選択同期では、同じ取得元の登録済みコピーから同期対象への参照も確認します。指定外のコピーが参照するファイルやディレクトリが同期で消える場合は、コマンド全体を変更前に停止し、参照元のスキル名と参照先を案内します。取得元の参照を修正したうえで、参照元も同期対象に含めて再実行してください。取得元から消えた参照元のコピーを残している場合も確認対象となるため、必要な参照を復元するか、不要な参照元のコピーを明示削除してから再実行します。指定外のコピーを自動更新・削除することはありません。

## Codex に登録を依頼する

このリポジトリを Codex の作業ディレクトリにして依頼してください。登録先が未指定の場合は、Codex 向けか Claude Code 向けか、ユーザー全体かプロジェクト単位かを確認してから実行します。指定済みの条件は聞き直しません。

```text
$install-skills このリポジトリのスキルを登録してください。
```

登録先と対象をまとめて指定することもできます。

```text
$install-skills 登録先を /path/to/project/.claude/skills にして、
edit-prose と review-workflow を登録してください。
```

コピー方式を選ぶ場合は、その指定も依頼に含めます。

```text
$install-skills 登録先を /path/to/project/.agents/skills にして、copy 方式で全登録してください。
```

エージェント向けの手順は [SKILL.md](../../.agents/skills/install-skills/SKILL.md) を参照してください。

## 一括リンクから移行する

以前の `agent-skills` から `skills/` 全体を参照するリンクがある場合も、通常の登録コマンドを実行します。登録元の `skills/` を指し、Git 管理対象でない一括リンクだけを移行します。

移行時は、利用できるスキルを暗黙に減らさないよう、名前の指定にかかわらず全配布用スキルの個別リンクを作成します。既存の同じ登録元への個別リンクは再利用します。全リンクの作成を確認してから一括リンクを削除し、その古い Git 除外記録を取り除きます。競合する個別項目があれば、一括リンクを維持して停止します。

一括リンク自体が Git 管理対象なら移行せず停止します。別の登録元や既存項目を指す `agent-skills` は削除せず残し、今回の個別登録とは分けて扱います。

旧一括リンクが残った状態で `--mode copy` を指定すると、変更前に停止します。先に方式未指定の通常登録で個別リンクへ移行し、その後に `--mode copy` を実行してください。

## 個別リンクとコピーの切替

同じ取得元を指す個別リンクは、`--mode copy` の通常登録でコピーへ直接切り替えられます。リンク先の元ファイルは変更・削除しません。別の取得元へのリンクや Git 管理対象は置き換えません。

コピーからリンクへ戻す場合は、コピーを明示削除してから通常のリンク登録を実行します。リンク方式の登録コマンドだけでコピーを直接置き換えることはありません。

```sh
python3 scripts/install.py "$HOME/.agents/skills" --mode copy --remove worktree-create
python3 scripts/install.py "$HOME/.agents/skills" worktree-create
```

## 更新・登録対象の変更

リンク方式では、取得元リポジトリで `git pull --ff-only` すると、登録済みスキルの内容はリンク経由で更新されます。新しいスキルは自動では登録されません。追加する名前を指定するか、名前を省略してインストーラーを再実行してください。

コピー方式では、取得元の内容を変更した後に、同じ `--mode copy` のコマンドを再実行します。スキル内のファイルの追加・更新・削除・改名を同期します。取得元から消えたスキル全体は自動削除せず、明示削除するコマンドを案内します。改名したスキルは新しい名前で登録し、旧名のコピーが不要なら明示削除してください。

全登録後に一部だけを指定して再実行しても、指定外の既存登録とその Git 除外記録は維持します。選択登録から全登録に変える場合は、名前を省略して実行します。

登録対象を減らす場合は、削除するスキル名を `--remove` に明示します。登録と削除は同時には指定できません。一括リンクがある場合は、先に通常の登録で個別リンクへ移行してください。

```sh
python3 scripts/install.py "$HOME/.agents/skills" --remove review-workflow edit-prose
```

削除するのは、登録元の `skills/<skill-name>/` を指すと確認でき、Git 管理対象でないリンクだけです。別の既存項目や Git 管理対象が指定に含まれていれば、リンクを一つも削除せず停止します。取得元のスキル本体は削除しません。更新で取得元から削除されたスキルのリンクも、同じ参照先だと確認できれば削除できます。未登録の名前は何も削除せず、専用範囲内に残った同名の除外記録だけを取り除きます。

削除後も、全登録コマンドを実行すると、その時点の全配布用スキルが再登録されます。

コピーの削除には、方式を明示します。

```sh
python3 scripts/install.py "$HOME/.agents/skills" --mode copy --remove worktree-create
```

方式未指定の `--remove` は従来どおりリンクだけを対象とします。コピーの削除でも、同じ取得元の管理情報が有効で、配置後の独自変更がなく、Git 管理対象でないことを確認します。問題がある対象が一つでもあれば、コマンド全体を変更前に停止します。取得元からスキルが削除されていても、この条件を満たせばコピーを明示削除できます。

### 個人用の同期指示

エージェントによる更新後に同期漏れを減らしたい場合は、この取得元リポジトリの個人用 `AGENTS.override.md` に、例えば次を記載します。個人用ファイル自体は `info/exclude` で除外し、Git 管理しません。

```markdown
配布用スキルを追加・更新したら、取得元リポジトリのルートで
`python3 scripts/install.py "$HOME/.agents/skills" --mode copy` を実行して同期する。
新規ファイルは同期前に Git 管理対象になっているか確認する。
失敗した場合は、対象・理由・残った状態を報告する。
```

この指示はエージェントが行う作業の補助です。手動編集や `git pull` では自動実行されません。取得元の更新とコピーの同期は別の操作であり、登録・同期だけの依頼で `git pull` を実行しません。

## Git 除外設定と失敗時の状態

登録先が Git リポジトリ内の場合は、`info/exclude` の `# BEGIN agent-skills` から `# END agent-skills` までの専用範囲で、各リンクまたはコピーと、コピー方式の管理ディレクトリを除外します。ほかの登録先や指定外のスキルの記録、専用範囲外のルールは維持します。worktree では共通の除外ファイルを使い、Git リポジトリ外では除外設定を行いません。

リンク方式では、対象にコピーの管理情報が残っている場合、除外記録を維持して停止します。それ以外で、今回の対象が別の項目や Git 管理対象に変わっていた場合は、その古い除外記録を専用範囲から取り除いて停止します。旧一括リンクが存在しない場合や別の項目になった場合も、その古い除外記録を取り除きます。既存項目自体は変更しません。

不正な専用範囲のマーカーや、`.gitignore` などによって除外が適用できない状態では、リンク変更前に停止します。実行中に状態が変わるなどして失敗した場合、途中までのリンク作成・削除や除外設定の変更は自動では巻き戻しません。終了コードと出力を確認し、既存項目を保護したまま原因を解消して再実行してください。

### コピー方式の管理情報と復旧

登録先直下の `.agent-skills-copy/` に、取得元の実パス、ファイル一覧・内容の SHA-256・ファイル権限、管理形式のバージョンをスキルごとに保存します。コピーをすべて削除した後も、管理ディレクトリとその除外記録は残します。指定外の情報を維持し、次の登録でも同じ管理形式を利用します。

#### 独自変更・衝突で停止した場合

既存項目、独自変更、依存不足、未対応のリンク、Git 管理対象、除外設定の問題を事前確認し、問題があればコピー本体・管理情報・Git 除外設定を変更せずに停止します。管理情報がない・壊れているコピーや、別の取得元のコピーを自動で管理対象にしません。

独自変更には、ファイルの追加・変更・削除だけでなく、コピー先の権限変更や空ディレクトリの追加も含みます。スキルを実行してできたキャッシュなども対象です。再同期・削除の前に内容を確認し、残す必要があるものは別の場所に退避してください。

再実行するには、追加したファイルや空ディレクトリをコピー先から取り除き、変更・削除した管理対象ファイルを前回配置時の内容と権限に戻してください。管理対象ファイルの退避だけでは、コピー先の欠落も独自変更と判定されるため再開できません。自動マージや強制上書きは行いません。

#### 実行途中で失敗・中断した場合

コピー本体と管理情報への変更を終え、その完了を記録した時点で、登録・同期・削除の「反映が確定」します。失敗時の扱いは、この時点の前後で異なります。

| 失敗した段階 | コピーと管理情報の扱い |
| --- | --- |
| 事前確認後、反映確定前の書き込み失敗 | 処理中のスキルを実行前の状態へ復旧します。 |
| 反映確定後、退避内容の片付けに失敗 | 反映後の状態を維持します。コピー・同期では新しいコピーと管理情報を実行前の状態へ戻さず、削除では削除済みの状態を保ちます。 |

完了済みの別スキルと、それまでに変更した Git 除外設定は残り得ます。反映途中でプロセスが中断した場合や復旧にも失敗した場合は、`.agent-skills-copy/transactions/` に退避内容と復旧情報を残します。

原因を解消して同じ対象でコマンドを再実行してください。未完了の処理の復旧、または反映確定後に残った片付けを先に行い、その後に指定した登録・同期・削除を進めます。退避内容や管理情報を手動で消して再実行しないでください。

#### 初期化中に中断した場合

管理ディレクトリと、スキルごとの退避内容・復旧情報を保存するディレクトリは、一時ディレクトリで所有情報を作成してから所定の場所へ配置します。所有情報は、そのディレクトリがインストーラーによって作られたことを識別するための記録です。スキルごとの復旧用ディレクトリの配置先は `.agent-skills-copy/transactions/<skill-name>/` です。

初期化中に強制終了すると、次の一時ディレクトリが残る場合があります。パスはいずれも登録先からの相対パスです。

| 初期化する対象 | 残る場合がある一時ディレクトリ |
| --- | --- |
| 管理ディレクトリ | `.agent-skills-copy-init-*` |
| スキルごとの復旧用ディレクトリ | `.agent-skills-copy/transactions/.<skill-name>-init-*` |

再実行では、これらの一時ディレクトリを利用・復旧対象とせず、新しく初期化して処理を開始します。残った一時ディレクトリを再実行時に自動削除することもありません。所有情報のない既存の `.agent-skills-copy/` を自動削除・再利用することはありません。

所定の場所への配置時に別の項目が作られても、空ディレクトリを含めて置き換えません。すでに配置済みの復旧用ディレクトリも上書きしません。上書きを禁止する配置操作を OS・ファイルシステムがサポートしない場合は、その配置を伴う登録・同期・削除を停止します。

## 検証と読み込みの確認

スクリプトを変更した場合は、リポジトリのルートで次を実行します。

```sh
python3 tests/test_install.py
```

自動テストはリンク方式の既存操作に加え、コピー対象、同期・削除・改名、相対参照と依存不足、方式切替、管理情報、独自変更の保護、Git 除外設定、失敗・プロセス中断後の復旧を確認します。取得元を見えなくした実ファイル配置も検証します。エージェントの一覧表示と実際の呼び出しは別途確認してください。

1. 確認するユーザーまたはプロジェクトの配置先に登録します。プロジェクト単位の場合は、そのプロジェクトでエージェントを起動します。
2. Codex CLI・IDE 拡張では `/skills` または `$`、Claude Code では `/` の候補一覧で登録した名前を確認します。表示されない場合はエージェントを再起動します。
3. 確認用の文書に対して、Codex では `$edit-prose`、Claude Code では `/edit-prose` を指定して構文確認を依頼し、登録したスキルを利用できることを確認します。選択登録したワークフローについては、参照先のスキルも読み取れることを確認します。

確認できない環境では、対象エージェント、ユーザー全体／プロジェクト単位のどこが未確認かと、上記の確認手順を検証結果に記載します。
