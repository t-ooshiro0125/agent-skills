# install-skills

登録先の `agent-skills` から、このリポジトリの配布用 `skills/` フォルダ全体へのシンボリックリンクを作成します。新しいスキルも再登録せずに反映され、各スキルは名前を指定して個別に呼び出せます。`install-skills` 自体は `.agents/skills/` に置くリポジトリ専用スキルで、登録対象に含めません。

## 依頼例

```text
$install-skills このリポジトリのスキルを登録してください。
```

このリポジトリを Codex の作業ディレクトリにして依頼してください。準備手順は [README の導入方法](../../README.md#導入方法)を参照してください。

## 登録先

登録先が未指定の場合は、ユーザー用の `~/.agents/skills/` に共通登録するか、特定のプロジェクトの `.agents/skills/` に登録するかを Codex が確認します。プロジェクト専用を選び、対象プロジェクトが不明な場合は、そのパスも確認します。回答をもとに登録先を確定してから実行します。

登録先が指定済みの場合は聞き直しません。依頼時に登録先を指定する場合は、絶対パスを添えてください。`/path/to/project` は対象プロジェクトの絶対パスに置き換えます。

```text
$install-skills 登録先を /path/to/project/.agents/skills にして、
このリポジトリのスキルを登録してください。
```

## スクリプトを直接実行する

Git・Python 3 が使える macOS・Linux の環境で、このリポジトリのルートから実行します。スクリプトは対話式ではなく、登録先を必須引数として受け取ります。ユーザー用に共通登録する場合は、次を実行します。

```sh
python3 scripts/install.py "$HOME/.agents/skills"
```

プロジェクト専用に登録する場合は、次のように指定します。

```sh
python3 scripts/install.py "/path/to/project/.agents/skills"
```

## 登録結果と移行

リンク作成には [scripts/install.py](../../scripts/install.py) を使います。同じ登録元を指す `agent-skills` があればそのまま利用します。別の既存項目や Git 管理対象が同名で存在する場合は、上書きせずエラーで停止します。

旧方式の個別リンクは、同じ登録元の同名スキルを指し、Git 管理対象でないものだけ、一括リンクの作成後に削除します。別の既存項目と Git 管理対象は残します。

登録先が Git リポジトリ内の場合は、`info/exclude` の `# BEGIN agent-skills` から `# END agent-skills` までの専用範囲で、一括リンクのパスだけを除外します。現在の登録先の旧個別スキルの除外記録は取り除き、ほかの登録先の記録と専用範囲外のルールは維持します。worktree では共通の除外ファイルを使い、Git リポジトリ外では除外設定を行いません。

一括リンクが別の項目や Git 管理対象に変わった場合は、再実行時にその古い除外記録を専用範囲から取り除き、エラーで停止します。`.gitignore` などによって除外が適用できない場合もリンク作成前に停止します。途中までに作成されたリンクや更新した除外設定は、自動では巻き戻しません。

登録対象を個別に選ぶ機能は [Issue #1](https://github.com/t-ooshiro0125/agent-skills/issues/1) で扱います。

## スクリプトを変更したときの検証

リポジトリのルートで次を実行します。

```sh
python3 tests/test_install.py
```

## 読み込みの確認

`/skills` または `$` を入力して登録したスキルを確認します。追加・更新が表示されない場合は Codex を再起動してください。

エージェント向けの手順は [SKILL.md](../../.agents/skills/install-skills/SKILL.md) を参照してください。
