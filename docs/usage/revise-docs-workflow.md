# revise-docs-workflow

文書の内容確認、指摘・変更案の検証、リライト、修正後の確認を一続きに行います。指示・ルール・運用文書と、日本語の一般文章が対象です。修正文の提示とファイルへの反映は、依頼された形式・範囲に従います。

[review-docs](review-docs.md) と [challenge-docs](challenge-docs.md) で内容と指摘を確認した後、文書全体の構成を整理し、[edit-rulebook](edit-rulebook.md) または [edit-prose](edit-prose.md) で意味のまとまりごとに点検・修正・再確認します。レビューの指摘箇所に限らず、依頼範囲全体を確認します。

原文と修正文を照合して意味・条件・断定の強さを保ち、修正文だけでも読者が理解・判断できるか確認します。修正案を出したことや文章を変更したことだけで、対応済みとは扱いません。

依頼文・会話と原文を確認し、読者の知識条件を決める必要があれば、開始時に「この分野に詳しくない人向け」「この分野の知識がある人向け」「元の文書に合わせる」から一度選べます。合わなければ自由文で指定できます。選択UIが使えない環境では番号・自由文で答えられます。知識条件や「元の文書に合わせる」が指定済みなら聞き直しません。役割や説明量だけが指定されていれば、その条件を保ち、知識条件だけを確認します。読者の知識と文体は分け、文体は別指定がなければ原文を尊重します。元の文書に合わせる場合も、分かりにくい説明は点検します。

## 作業の記録

付属スクリプトで原文と依頼条件を保存し、構造に基づく分割候補を意味のまとまりへ調整します。実行には Python 3.10 以上と、操作手順で案内する依存パッケージが必要です。一つずつ本文と点検結果を保存し、変更によって古くなった確認はやり直します。スクリプトはモデルを呼び出さず、意味や読みやすさの判断は各スキルが担います。

読者の属性に加え、依頼で示された理解上の困りごとと、改善後に理解・判断したいことを引き継ぎます。必要な観点を先に ID で登録し、対象ごとの具体的な完了条件を計画にします。現行本文を点検した結果は別入力にし、全基準との対応と版の一致を確認します。情報を保ったことだけで読みやすさも十分とはせず、適用しない基準にも理由を残します。

ユーザーの指摘と、選んだ読者に応じた全体点検から、意味を知らないと理解できない用語・対象が分からない抽象表現・結論と理由がつながらない箇所を選び、個別に登録します。編集前に困りごとと理解目標の対応を確かめ、用語の意味の不足を用途や制限だけの目標へ狭めません。理解目標と現行本文の説明箇所を結び付け、同じ節の別の表現を確認しただけで全体を合格にはしません。登録した表現や引用の版が変わったら再確認します。

重要な判断に関わる箇所は、利用できる別エージェント等に修正文・実際の読者設定・質問だけを渡して読者確認します。理解目標の質問に加え、自分の言葉で説明してもらい、質問の外にある用語・理由・条件の不足も拾います。本文の根拠と答えられない点を受け取り、新たな不足を対象・理解目標へ追加して再修正・保留へ戻します。全段落の二重処理は求めず、外部検索や知識で説明を補いません。

未処理・再確認待ち・必要な確認記録の不足がある間は、完成版として出力できません。対象ごとの反復回数には上限を設け、未解消なら具体案・理由・必要な判断を付けて保留にします。保留を残して他の編集は進められますが、保留まで解決したとは報告しません。必要な情報・判断が加わって再開する場合は、`extend-limit` で理由付きの上限引き上げを行えます。過去の回数は保持し、対象を再確認待ちへ戻して編集・確認します。操作は [作業状態の操作手順](../../skills/revise-docs-workflow/references/work-state.md) を参照してください。

計画に確認結果や合否を混ぜたり、本文の変更有無で合否を自動登録したりしません。この仕組みで検査するのは記録の有無・対応・版であり、実際の再読や内容の妥当性を証明するものではありません。既存の形式1の状態は、操作手順の `upgrade` で履歴を保って再確認へ移行します。

## 判断待ちの扱い

依頼範囲で意味を確定できる言い換えや整理は、そのまま進めます。結論が変わる複数の解釈、仕様・方針の選択、依頼範囲外の追加・省略は、具体案・理由・推奨・影響範囲を示して確認します。その判断に依存しない編集は続けます。

原文外の説明は、根拠と挿入先を含む追加案を作ります。説明追加が認められた範囲で反映し、範囲外の案や確認できない内容は保留事項として示します。終了時には、修正版・主な変更と、残った確認・判断事項を提示します。

## 依頼例

```text
$revise-docs-workflow このファイルをお願い。対象: …
```

読者が未指定なので、最初に選択してから確認・編集へ進みます。読者を既に決めている場合は、依頼に添えられます。

```text
$revise-docs-workflow この分野の知識がある担当者向けに、原文の判断・条件を保って整理してください。対象: …
```

指摘と修正案の提示だけなら [review-docs-workflow](review-docs-workflow.md)、内容レビューを含めず構成・表現を直接整えるなら [edit-prose](edit-prose.md) または [edit-rulebook](edit-rulebook.md) を使います。

手順は [SKILL.md](../../skills/revise-docs-workflow/SKILL.md)、表示用メタデータは [agents/openai.yaml](../../skills/revise-docs-workflow/agents/openai.yaml) を参照してください。
