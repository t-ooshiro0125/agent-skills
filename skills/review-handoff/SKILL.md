# Review Handoff

## 目的と対象

レビューと検討を終えた後に、今回実装する項目を開発者向けの簡潔な Markdown の対応指示にまとめる。コードレビュー自体には使用しない。

## 基本方針

現在の会話にあるレビュー結果と議論をもとに、ユーザーの最終判断を優先する。合意済みの必須修正と、ユーザーが選んだ任意改善は採用する。採否が未確定の任意改善は、次節の基準で選別する。

現在の会話から対象ファイルや判断を特定できる場合は、ユーザーに聞き直さない。会話を踏まえても、実装指示を確定するための重要な情報が不足している場合だけ、ユーザーに確認して停止する。レビューにない指摘を追加したり、実装内容を推測で補ったりしない。ファイル編集、コマンド実行、実装は行わない。

## 未確定の任意改善

ユーザーが採否を決めていない任意改善は、次を満たすものだけを採用する。

- リポジトリの規約・既存パターンに沿っている。
- 小さな変更で、可読性、保守性、安全性を明確に改善する。
- 改善効果に対して複雑化が大きくない。

## 出力形式

採用した項目は、今回実装するかどうかとは別に、対応の性質に応じて「必須対応」と「任意対応」に分類する。ユーザーが採用した任意改善も、改善の性質が任意なら「任意対応」とする。

対応項目がある場合は、項目があるセクションだけを、必ず単一の `markdown` コードブロックで出力する。対応項目がない場合は「対応項目はありません。」と返す。

```markdown
## 必須対応

- `<対象ファイル>`
  - `<具体的な変更>`を実施する。

## 任意対応

- `<対象ファイル>`
  - `<具体的な変更>`を実施する。
```
