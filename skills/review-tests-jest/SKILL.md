# Review Tests Jest

## 目的と使い方

Jest テストの回帰検知力と構成をレビューする。実行前に [review-tests](../review-tests/SKILL.md) を読み、対象範囲・手順・指摘基準・出力形式に従う。共通観点に次の Jest 固有の観点を加え、一度のレビューとして実行する。ファイルの編集は行わない。

## Jest 固有の確認

- Promise、`async` / `await`、callback の完了をテストが待ち、検証前に成功扱いにならないか。失敗するはずの非同期処理が成功しても通る構造になっていないか。
- `jest.fn`、spy、module mock が対象処理まで置き換えていないか。mock の呼び出し履歴、実装、spy の復元を区別し、設定と hook によってケース間の状態が漏れないか。
- fake timer を使う場合、対象の timer と Promise の処理が検証前に完了するか。時刻や timer の変更を後始末し、実時間の待機に不必要に依存していないか。具体的な API は利用先の Jest バージョンで確認する。
- `testMatch` / `testRegex`、除外設定、projects、`.only` / `.skip` / `.todo`、実行時フィルタを確認し、対象テストが収集・実行されるか。
- Node / jsdom、transform、module 解決、setup ファイルと mock が、検証したい挙動に合うか。テスト環境だけで成立する挙動を本番の保証として扱っていないか。
- snapshot は守る契約が明確で、変更時に意味のある差分を確認できるか。更新するだけで回帰を隠す構造になっていないか。
- ケース名の言語、assertion 数、mock の許容範囲は利用先の規約に従う。規約がなければ表記や数だけで違反としない。

## コンポーネントテストの場合

利用先の UI フレームワークとテストツールの規約に従う。描画更新や利用者の操作を待ってから、対象コンポーネントの責務を検証しているか確認する。子コンポーネントの内部仕様を重複検証せず、stub が必要な連携まで隠していないかも確認する。DOM、mount したコンポーネント、event listener などがケース間に残らないか調べる。

## 検証と報告

利用先の設定と package script を確認し、対象テストと必要な lint を実行する。コマンドに渡したファイル指定が実際の実行範囲に反映されるか確認する。結果は共通スキルの出力形式でまとめ、共通観点と Jest 固有の指摘を重複して列挙しない。
