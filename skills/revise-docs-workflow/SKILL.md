# Revise Docs Workflow

## 目的と対象

既存文書を対象に、内容の問題を調べて指摘・変更案を検証し、依頼範囲で修正して、実際の修正文で問題が解消したか確認する。修正文の提示と対象ファイルへの反映は、依頼された形式・範囲に従う。文書に記載された業務操作や外部サービスへの送信・公開は、編集の依頼に含めない。

指摘と修正案を出し揃えるだけなら [review-docs-workflow](../review-docs-workflow/SKILL.md)、構成・表現の確認や直接のリライトだけなら [edit-prose](../edit-prose/SKILL.md) または [edit-rulebook](../edit-rulebook/SKILL.md) を使う。

## 工程と引き継ぎ

各工程の前に担当スキルの `SKILL.md` を読み、具体的な編集基準を参照する。本スキルでは、依頼に応じた確認観点の選定と引き継ぎ、確認の進め方を定める。レビュー・反証スキルの「終了」「編集しない」は当該工程だけに適用し、結果を引き継いで次の工程へ進む。工程間では停止せず、文書の修正は後続の編集工程で依頼範囲に従って行う。

1. 依頼範囲の原文全体を読み、目的・想定読者・利用場面、依頼者が示した理解上の困りごと、改善後に理解・判断できるようにしたいこと、変更範囲・出力形式・保持条件を把握する。[依頼から確認観点を決める](#依頼から確認観点を決める)に従い、必要な観点を選ぶ。原文と作業中の修正文を区別して保持し、指定済みの条件は聞き直さない。職種・役割だけから分野固有の用語を既知とせず、不明な読者像も初心者へ固定しない。
2. [review-docs](../review-docs/SKILL.md) で内容を確認し、[challenge-docs](../challenge-docs/SKILL.md) で指摘と変更案を検証する。選んだ確認観点と依頼者の困りごとを、有効な指摘、撤回・修正した指摘、根拠、未確認事項とともに後続へ引き継ぐ。指摘の妥当性と、内容変更が依頼で認められているかを区別する。
3. 文書全体の大きな構成を整理してから、[作業状態の操作手順](references/work-state.md)を読み、付属スクリプトで原文・依頼条件・作業本文を保存する。構造に基づく分割候補を意味のまとまりに調整し、依頼範囲全体を登録する。指示・ルール・規約・運用文書は [edit-rulebook](../edit-rulebook/SKILL.md)、日本語の一般文章は [edit-prose](../edit-prose/SKILL.md) を使い、後述の手順で順に点検・修正・再確認する。
4. 修正済みの全文を通して読み、[全文の確認と終了](#全文の確認と終了)に従って、各箇所の修正と文書全体のつながりを確認する。
5. 依頼された形式の修正版、主な変更、残った確認・判断事項を提示する。各工程の指摘や作業記録をすべて再掲する必要はない。

## 依頼から確認観点を決める

個別の問題を見つける前に、依頼の種類に応じて次の基本観点を選び、安定した ID・確認段階・観点の説明を依頼条件に登録する。読みやすさの改善では、意味の保持だけでなく、用語と対象・判断内容の理解を含める。基本観点で扱えない依頼固有の改善目標は、必要なものだけ ID を追加する。

| ID の例 | 段階 | 選ぶ依頼と確認観点 |
| --- | --- | --- |
| `meaning` | まとまりごと | 編集全般。元の意味・条件・断定の強さを保つ |
| `terms` | まとまりごと | 用語説明・読みやすさの改善。読者に必要な用語の意味や役割が分かる |
| `referents` | まとまりごと | 対象や関係・読みやすさの改善。何について何を説明・確認・判断するか分かる |
| `comparison` | 全文 | 編集全般。原文の情報と保持条件を全文で照合する |
| `coherence` | 全文 | 構成・読みやすさの改善。原文なしでも説明順序と文のつながりを追える |

選んだ観点を、対象ごとの具体的な完了条件へ落とし込む。用語の観点なら、その箇所で読者が何の意味や役割を理解できればよいかを記す。内容レビューの指摘だけを完了条件にせず、依頼から選んだ観点も残す。全文で見る観点は全文確認へ引き継ぐ。既知の困りごとがない場合は、その旨を記録し、推測で読者の知識を決めない。

## 指摘と修正文の対応

付属の [revision.py](scripts/revision.py) で、原文・最新の修正文・依頼条件と、各対象の次の記録を保持する。スクリプトは候補の分割、次の対象の取得、本文と確認結果の保存、未処理の検出、全文の再構成を担う。内容の妥当性や読みやすさは担当スキルで判断し、記録の存在だけで保証されたとは扱わない。モデルの呼び出しや外部サービスへの操作は行わない。

- 対象箇所：見出しや原文の引用。移動に備え、行番号だけに依存しない。
- 問題と根拠：誰が何を理解・判断できないかと、その根拠。
- 修正案と保持条件：どう直すかと、変えてはいけない意味・条件・断定の強さ。
- 完了条件：登録した観点の ID ごとに、実際の修正文で何を理解・判断できれば解消と扱うか。
- 状態と理由：未処理、再確認待ち、修正して確認済み、変更不要、情報・判断待ちとして保留を区別する。既存の指摘を変更不要と判断した場合も理由を残す。何を点検し、実際の本文で何を確認したかを記録し、「OK」「変更なし」だけで済ませない。

## まとまりごとの点検と修正

まとまりは固定の文字数・文数・段落数で区切らず、一つの説明や判断を理解できる範囲とする。分割候補は見出し・段落・表・リスト・コードブロックなどを保つ。候補の分割・結合は本文を欠落・重複させずに行い、表の一行には列名と共通条件、手順には適用条件を添える。編集対象と参照用の文脈を区別し、必要なら原文・現行全文・関連箇所へ戻る。

次の対象を一つ取得し、依頼条件・登録した観点・見出し・前後・保持条件を読む。問題・修正案・保持条件・ID ごとの具体的な完了条件を計画入力に登録し、担当の編集スキルで点検・修正する。その後、現行の本文と参照文脈を実際に読み、基準ごとの確認結果を別入力で保存してから次へ進む。計画には確認結果や合否を混ぜない。

- 全基準を点検して問題がなければ、文章を変えずに変更不要として記録し、次へ進む。意味や条件を保持したことだけで、読みやすさも十分だとは判断しない。
- 原文から意味を確定でき、依頼範囲で修正できる場合は、その場で作業中の文章を修正する。同じ箇所を再点検し、保持条件と完了条件を満たしたことを確認してから、修正して確認済みとする。修正案の提示や文章を変更したことだけで対応済みにしない。
- 情報や判断が必要な場合は、具体案と保留理由、必要な確認・判断を記録する。未処理や解決済みと混同せず、その判断に依存しない編集を続ける。

適用しない基準にも、対象に適用しない理由を結果として残す。必要な説明の根拠や採用判断が不足する場合は、適用外ではなく保留とする。補助コードでも、本文の変更有無による合否の自動選択や、事前に用意した確認結果の自動登録は行わない。同じ結論・観察内容での再確認は許容し、文言を変えることを再読の証拠にしない。

修正後も問題が残れば同じ箇所を点検・修正する。改善を確認できない場合や、情報・判断の不足、条件の不両立がある場合は、具体案・理由・必要な判断を残して保留にする。対象ごとの反復上限を作業開始時に設定し、上限到達を合格と扱わない。調査で解決できる不足は内容確認の工程へ戻り、承認が必要な変更は後述の条件に従う。

確認結果は点検した対象・本文・参照文脈・基準の版に結び付け、保存時に新しい版へ差し替えない。必要な全 ID に現行版の結果があることを検査する。本文・依頼条件・基準の変更で古い確認を使わず、後から構成や共通の前提を変えた場合は、確認済みも含めて影響する対象を再確認待ちへ戻す。意味上の影響範囲は担当者が指定し、全文の確認もやり直す。再分割しても既存の指摘・確認履歴と反復回数を捨てない。

## 確認が必要な変更

原文から意味を確定できる言い換えや整理は、リライトの依頼範囲で進め、修正のたびに承認を求めない。ユーザーが既に採用した案も、その条件の範囲で反映する。

原文に結論が変わる複数の解釈がある場合、仕様・方針の選択が必要な場合、依頼範囲外の情報追加・省略が必要な場合は、修正候補、変わる意味、推奨、影響する箇所を示して確認する。文書全体の方向に関わる判断は先に確認し、局所的な判断に依存しない編集は続け、関連する質問をまとめる。回答待ちを採用や許可として扱わない。

原文外の説明が必要な場合は、内容確認の工程で根拠を調べ、追加内容と根拠・挿入先を具体化する。説明追加まで認められた依頼なら、その範囲で反映する。依頼範囲外なら具体案を確認対象として残し、未採用の内容や不明な事実・判断を推測で補わない。

リライトによって生じた意味や断定の強さの変化は、原文を保つように修正する。内容の判断自体を変更する案は、それとは別の変更案として扱う。

## 全文の確認と終了

全文段階に登録した観点を具体的な完了条件へ落とし込み、計画入力に登録する。担当の編集スキルの最終確認に加えて、次の二つの観点で修正済みの全文を読み、登録した全 ID の結果を別入力で保存する。

- 原文との照合：情報・数値・条件・結論・断定の強さが、依頼で認められた変更以外で変わっていないか。
- 修正文だけでの確認：想定読者が、原文や編集理由を参照せず、何について何を説明・判断しているか理解できるか。説明の順序、文同士のつながり、用語の扱いに問題が残っていないか。

各指摘と依頼された改善の完了条件を実際の修正文で確認し、問題が残れば影響するまとまりを再確認待ちへ戻す。スクリプトで、未処理・再確認待ち・未確認の基準がなく、現行版の全文確認が記録され、保留事項の理由・具体案・必要な判断が明示されていることを確かめてから再構成する。記録の有無・対応・版の一致は、内容の妥当性や実際の再読を証明するものではない。読みやすさは修正文で別途確かめ、保留部分まで修正完了したとは報告しない。
