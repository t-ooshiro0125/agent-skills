# Worktree Cleanup

## 対象と確認

worktree の一覧確認・削除・整理を依頼された場合に使う。利用先の指示ファイルと規約を読み、対象リポジトリの `git worktree list --porcelain` を確認する。専用スキルから環境確認などの前提が指定されていれば従う。

一覧や調査だけの依頼では変更しない。削除対象を絶対パスへ解決し、ユーザーの指定と一覧を照合する。対象が曖昧なら状態を調べて候補を示し、削除対象を確認する。

## worktree の削除

`target` は確認済みの対象 worktree の絶対パスとし、削除前に次のコマンドで変更・未追跡ファイル・除外対象ファイルを列挙する。列挙に失敗した場合は削除しない。

```sh
git -C "$target" status --short --branch --ignored --untracked-files=all
```

- tracked ファイルの変更、staged・unmerged、除外対象ではない未追跡ファイルがある worktree は削除しない。未コミット変更の破棄と対象パスが明示された場合だけ、指定された範囲で強制削除を検討する。
- `!!` は除外対象を示し、存在するだけで dirty とは扱わない。ただし除外対象も削除時に失われるため、列挙された各項目について、再生成可能な生成物、保存が必要なローカルデータ、共有リンクを区別する。保存が必要なデータがある、または保存要否が判断できない場合は削除を保留し、扱いを確認する。共有リンクは参照先を確認し、リンク先の共有元は削除しない。
- 対象 worktree のプロセスが稼働中なら、利用先の停止手順を確認して対象だけを止める。停止が依頼範囲や規約で認められない場合は、その理由を示して削除を保留する。
- 通常は `git worktree remove` を使い、保護エラーを `--force` やディレクトリの直接削除で回避しない。primary worktree はこの手順で削除しない。ブランチは削除依頼が別途明示されている場合だけ操作する。

## stale metadata の整理

まず `git worktree prune --dry-run --verbose` で対象を確認する。単なるパスの一時的な不在や利用中の worktree を不要と扱わず、lock と利用状況を確認する。整理を依頼され、対象が確定した場合だけ `git worktree prune --verbose` を実行する。

## 完了確認と出力

操作後の一覧と残った作業状態を確認し、削除・整理した対象、残した対象と理由を示す。失敗時は残った worktree と metadata の状態を確認して報告し、自動で強制削除・ブランチ削除・巻き戻しを行わない。
