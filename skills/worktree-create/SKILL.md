# Worktree Create

## 目的と対象

進行中の作業を元のフォルダに残し、新しい worktree の作成または既存 worktree の再利用によって別フォルダで作業を開始できる状態にする。Issue の存在は前提にしない。Issue の取得やローカルファイルの共有は行わない。

## 適用条件

worktree の作成・再利用が、ユーザーの依頼・選択、または利用先リポジトリの明示的な指示に含まれる場合に実行する。このスキルを使った worktree 準備の明示依頼も含む。

通常の実装依頼、Issue 番号の指定、現在のブランチが別 Issue 用であることだけを、worktree の作成・再利用の指示として扱わない。相談・調査だけの場合は調査と提案までにとどめ、スキル自体の作成・編集依頼を worktree 作成の指示として扱わない。

利用先の規約がブランチ切替と worktree の選択確認を求めている場合は、方法が未指定のときだけ確認し、選ばれた方法に従う。既に作成・再利用が依頼範囲に含まれ、必要な情報が揃っている場合は、形式的な再承認を求めない。

## 作業前の確認

- 対象リポジトリにある指示ファイル（`AGENTS.md`、`AGENTS.override.md` など）と開発手順の Git 関連箇所を読み、既存のユーザー指示とブランチ命名規則に従う。これらのファイルが存在することは必須条件にしない。
- `git status --short --branch`、`git worktree list --porcelain`、ローカル・リモートのブランチと除外設定を確認する。元のブランチ・差分・未追跡ファイル・インデックスの状態を記録する。
- ユーザーの指定、利用先の規約、Git の実際の状態から、基点・ブランチ名・作成先を特定する。既に指定された内容は聞き直さず、判断材料が不足する場合だけ確認する。デフォルトブランチやリモート名を `main`・`origin` と決めつけない。
- 作成先は元フォルダの隣など、別の worktree 内ではない場所を選ぶ。
- 未コミット変更・未追跡ファイル・Git の除外対象ファイルは、通常の `git worktree add` では引き継がれない。必要なファイルがあれば完了報告で残った準備として示す。

## 作成・再利用の手順

元の作業ツリーでは `git switch`、`git stash`、`git reset`、`git clean` を行わない。既存の変更を自動でステージ・コミットしない。ブランチ作成用の既存スクリプトが現在のフォルダのブランチを切り替える実装なら、元フォルダで実行しない。

外部プロセスは worktree だけでは分離されない。同時操作をする場合はインスタンスと接続先も分ける。接続設定の変更やアプリの起動は依頼範囲に含まれる場合だけ行う。

`source`、`target` は実際に確認した絶対パス、`branch` は規約に沿うブランチ名、`base` は確認した基点とする。リモートを使う場合の `remote` は指定・規約・Git の設定から特定し、複数候補があって判断できなければ確認する。個人環境の絶対パスをスキルやスクリプトに固定しない。

1. 作成方法・名前・作成先を決める。新規ブランチの作成、既存ブランチの利用、既存 worktree の再利用から、ユーザーの意図と Git の状態に合う方法を選ぶ。ブランチ名はユーザーの指定と利用先の命名規則を優先し、規則がなければ作業内容が伝わる簡潔な名前を選ぶ。プレフィックスや機械的な連番を固定しない。

   新しい worktree の作成先が存在しないこと、新規ブランチ名がローカル・リモートの既存ブランチと重複しないことを確認する。リモートがない場合はローカルの競合を確認する。リモート側の同名ブランチは、ローカルの追跡参照だけで判断せず、確認対象のリモートへ問い合わせる。

   ```sh
   git -C "$source" ls-remote --heads "$remote" "refs/heads/$branch"
   ```

   問い合わせの成功と出力を確認し、取得失敗を「同名ブランチなし」と扱わない。同名ブランチがあれば新規作成せず、ユーザーの意図に応じて作業内容が分かる別名か既存ブランチの利用を選ぶ。勝手に再利用へ切り替えない。

   既存ブランチの利用を明示された場合は新規作成と区別する。別 worktree で使用中なら、その worktree の再利用を検討し、強制的に切り替えない。
2. 必要なリモート情報を取得し、基点を確定する。新規ブランチの基点はユーザーの明示指定を優先し、指定がなければ利用先の規約に従い、原則として fetch 時点のリモートデフォルトブランチを使う。規約が要求する更新・同期手順は省略したり別の方法に置き換えたりしない。この標準手順ではローカルのデフォルトブランチをチェックアウト・更新する必要はない。

   新規ブランチで基点の指定も規約による指定もない場合は、選んだリモートの現在のデフォルトブランチを確認する。ローカルのリモート HEAD 設定だけで決めず、次の出力にある HEAD の参照先（`refs/heads/` を除いたブランチ名）を `default_branch` に特定する。

   ```sh
   git -C "$source" ls-remote --symref "$remote" HEAD
   ```

   特定したブランチを明示して取得し、取得後の参照とコミットを確認して `base` に使う。

   ```sh
   git -C "$source" fetch "$remote" "+refs/heads/$default_branch:refs/remotes/$remote/$default_branch"
   git -C "$source" rev-parse --verify "refs/remotes/$remote/$default_branch^{commit}"
   ```

   `base` は `refs/remotes/$remote/$default_branch` とする。refspec の `+` はリモート追跡参照の非 fast-forward 更新を許可する。更新先は `refs/remotes/*` に限定し、ローカルの作業ブランチやデフォルトブランチを強制更新しない。fetch によるリポジトリ共通の参照情報の更新と、元の作業ツリーのファイル・インデックスの変更は区別する。

   既存ブランチ・worktree の利用では、基点を勝手に変更しない。目的のブランチがリモートにしかない場合は、対象リモートとブランチを特定し、上と同じ取得方法で得たリモート追跡参照を `remote_branch` とする。Git の暗黙的なブランチ推測には依存しない。
3. worktree を作成・再利用する。前提が満たされたら、確定した方法で worktree を用意する。既存 worktree を再利用する場合や、利用先の手順で既に worktree とブランチを作成した場合は、新規作成しない。それ以外の場合は、次のうち選んだ方法のコマンドを実行する。

   新規ブランチを作る場合：

   ```sh
   git -C "$source" worktree add -b "$branch" "$target" "$base"
   ```

   ローカルにある既存ブランチを使う場合：

   ```sh
   git -C "$source" worktree add "$target" "$branch"
   ```

   リモートにしかない既存ブランチから、追跡するローカルブランチを作る場合：

   ```sh
   git -C "$source" worktree add --track -b "$branch" "$target" "$remote_branch"
   ```

4. 結果と元の作業状態を確認する。利用する worktree 内の指示ファイルを読み、元側の個人ルールも維持する。「完了確認と出力」に従って確認し、結果を報告する。

## 作成できない場合と失敗時の対応

必要なブランチが使用中、目的のブランチが既に存在する、規約で要求された更新・同期ができない場合は、既存 worktree の状態を調べ、再利用などを判断する。他の作業を強制的に切り替えたり、規約を回避してリモート追跡ブランチ起点に変更したりしない。判断に必要な情報が足りなければユーザーに確認する。

リモートの確認・取得が必要な場合に、リモートがない、fetch が失敗した、デフォルトブランチを特定できないときは、作成に進まず、利用可能な情報を調べる。古い参照や推測した基点で代替せず、判断材料が不足する場合だけユーザーに確認する。

途中で失敗したら、実際の worktree・ブランチの状態を確認して報告する。復旧のために自動で削除・強制更新・巻き戻しをせず、再開時は実在する状態を確認し、重複作成を避ける。

## 完了確認と出力

- 利用する worktree の場所・ブランチ・基点のコミットを確認する。新規作成では確認した基点と一致すること、既存ブランチ・worktree の利用では意図せずコミットを変更していないことを確認する。
- 元の作業ツリーのブランチ・差分・未追跡ファイル・インデックスが変わっていないことを確認する。並行作業による変化は自分の操作と区別し、巻き戻さない。

作成・再利用した場所、ブランチ、基点、残った準備を簡潔に報告する。ローカルファイルの共有・実装・push・PR 作成へ自動で進まない。
