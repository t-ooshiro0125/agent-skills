# Worktree From Issue

## 目的と対象

Issue 用 worktree の準備を依頼された場合に、別フォルダで作業を開始できる環境を準備する。相談・調査だけの場合は調査と提案までにとどめ、スキル自体の作成・編集依頼を worktree 作成の指示として扱わない。

Issue に依存しない作成・再利用だけなら [worktree-create](../worktree-create/SKILL.md)、既存 worktree の共有設定だけなら [worktree-link-local](../worktree-link-local/SKILL.md) を使う。

## 準備の手順

各工程の実行前に、担当スキルの `SKILL.md` を読み、手順・判断基準・安全条件に従う。指定済みの情報は聞き直さず、必要な情報を調査しても判断できない場合だけユーザーに確認する。作成・共有が依頼範囲に含まれていれば、形式的な再承認は不要とする。

1. 対象リポジトリの指示ファイルと開発規約を読み、Issue の目的・依存関係・必要な作業環境を確認する。GitHub Issue の場合は `gh issue view` を使う。ほかの Issue 管理システムでは、利用可能な情報と利用先の方法で確認する。Issue の編集や同期ファイルの書き換えは行わない。
2. Issue の情報、ユーザーの指定、リポジトリの規約から、基点・ブランチ名・作成先とローカルファイル共有の必要性を判断する。

   依存 Issue が作業開始や基点に影響するか調べ、未統合の変更が必要な場合は、その変更を含む基点を検討する。依存関係があるだけで機械的に基点を変更せず、ユーザーの指定と `worktree-create` の基点選択ルールに従う。
3. [worktree-create](../worktree-create/SKILL.md) の手順で worktree を作成・再利用する。基点やブランチの更新規約を回避せず、元の作業状態を保護する。
4. 共有が必要なら、Issue 固有の情報とユーザーが指定した共有対象を [worktree-link-local](../worktree-link-local/SKILL.md) へ引き継ぎ、同スキルに従って設定する。共有が不要ならリンク設定は行わない。

失敗時は各担当スキルの手順に従って実際の状態を確認し、完了済みの操作と残った準備を報告する。自動で削除・強制更新・巻き戻しをせず、再開時は実在する状態から進める。

## 完了確認と出力

各担当スキルの完了確認を行い、作成・再利用した worktree の場所、ブランチ、基点、共有対象、提示した代替案、残った準備を簡潔にまとめる。別途依頼されて実行したコピーがあれば、その結果も区別して示す。Issue の実装・push・PR 作成へ自動で進まない。
