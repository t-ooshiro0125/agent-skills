# Worktree Link Local

## 目的と対象

同じリポジトリの既存 worktree 間で、必要なローカル専用ファイル・ディレクトリのシンボリックリンクを設定する。worktree・ブランチの作成や Git のインデックス操作は行わない。

共有を依頼された場合に実行する。相談・調査だけの場合は調査と提案までにとどめ、スキル自体の作成・編集依頼を共有の実行依頼として扱わない。

## 作業前の確認

- 共有元・共有先の worktree と共有対象を特定する。指定済みの情報は聞き直さず、判断に必要な情報が不足する場合だけ確認する。
- 対象リポジトリに存在する指示ファイル（`AGENTS.md`、`AGENTS.override.md` など）と開発規約を読み、既存のユーザー指示に従う。特定の指示ファイルの存在を必須条件にしない。
- `git status --short --branch`、`git worktree list --porcelain` と除外設定を確認し、共有元・共有先のブランチ・差分・未追跡ファイル・インデックスの状態を記録する。元の作業をステージ・コミット・切替・削除しない。
- `source`、`target` は確認した worktree ルートの絶対パスとする。個人環境の絶対パスをスキルやスクリプトに固定しない。

## 共有対象の選定

共有対象は、ユーザーの依頼と、確認した指示ファイル・開発規約にある指定から特定する。指定がない場合は、共有の必要性と影響を確認して対象を選び、判断に必要な情報が不足していればユーザーに確認する。パスは対象リポジトリのルートを基準とし、Git の除外対象ファイルを一括共有せず、必要なパスを明示する。リンク対象は共有元で Git の除外対象になっているパスに限る。

共有対象の記載方法を案内する場合は、[共有対象と Git 除外設定](references/local-files.md#共有対象の指定)を参照する。共有依頼だけで、指定を記載する文書を自動作成・変更しない。

- 個人ルール、リポジトリ内のローカルスキル、ローカル専用のツール・依存環境は、必要なものだけ共有する。
- ユーザー共通のスキル保存先はリンク不要とする。
- Git 管理対象のコード・仕様書などは worktree ごとに保持し、未追跡でも将来 Git 管理するものはリンクしない。

### 共有による影響と代替案

共有先でリンク経由で編集すると共有元にも反映されるため、共有する依存環境の変更では両方への影響を考慮する。元フォルダを移動・削除するとリンクが切れるため、そのまま残す。こうした相互影響や元フォルダへの依存が適切でない場合、または Git の除外対象ではない未追跡ファイルを扱う場合は、コピーや worktree ごとの個別管理を代替案として提示する。コピーは標準手順に含めず、ユーザーが明示的に依頼した場合だけリンク設定とは別の操作として扱う。その場合も共有先の既存ファイルを上書きしない。

外部プロセスは worktree だけでは分離されないため、同時操作をする場合はインスタンスと接続先も分ける。接続設定の変更やアプリの起動は依頼範囲に含まれる場合だけ行う。

## リンク設定の実行

補助スクリプトは既存 worktree 間のリンク設定だけを扱い、ブランチの作成や Git のインデックス操作は行わない。全対象を事前確認し、適用時に相対リンクを作成して、Git 共通ディレクトリ内の `info/exclude` に除外設定を追加する。この設定は同じリポジトリのすべての worktree に適用される。除外パターンの扱いは、必要に応じて[共有対象と Git 除外設定](references/local-files.md#リンクと-git-除外設定)を参照する。

既存リンクが同じ参照先を指していれば再実行できる。異なる参照先のリンク、既存ファイル、Git 管理対象のファイルは上書きしない。共有元が存在しない場合はエラーになるため、必要性を判断して対象から外すか、先に用意する。

共有先の `.gitignore` にある除外解除パターンがリンクの除外を妨げる場合は、dry-run・適用のどちらも、リンクや除外設定を書き込む前に停止する。エラーに示されたファイル・行・パターンを確認し、リンク対象から外すか、除外ルールの意図を判断する。リポジトリの `.gitignore` を自動で書き換えない。

1. 特定した共有対象を `--link` に指定して dry-run を実行する。デフォルトでは変更を適用しない。次は `AGENTS.override.md` と `.agents/skills` を共有する場合の例で、`skill_dir` はこの `SKILL.md` のあるディレクトリとする。

   ```sh
   python3 "$skill_dir/scripts/link_local.py" \
     --source "$source" --target "$target" \
     --link AGENTS.override.md --link .agents/skills
   ```

2. 出力が依頼範囲と一致していれば、同じ引数に `--apply` を付けて適用する。作成・共有が既に依頼されていれば、形式的な再承認は不要。

失敗時は実際の状態を確認し、作成済みリンクと除外設定を報告する。I/O エラーや適用中の除外設定の変更で途中停止した場合は、変更が残り得るため、状態を確認して再実行する。自動で削除・巻き戻しをせず、共有元のデータを削除して復旧しない。

## 完了確認と出力

- 各リンクの参照先と、意図せず追跡対象になっていないことを `git status --short` と `git check-ignore` で確認する。
- 共有元・共有先のブランチ・既存の差分・未追跡ファイル・インデックスが意図せず変わっていないことを確認する。並行作業による変化は自分の操作と区別し、巻き戻さない。

共有元・共有先、共有対象、作成・再利用したリンク、更新した除外設定、提示した代替案と残った準備を簡潔に報告する。コピーを別途依頼されて実行した場合は、その結果も区別して示す。実装・push・PR 作成へ自動で進まない。

## 補助スクリプトを変更したときの検証

`python3 "$skill_dir/tests/test_link_local.py"` を実行する。Python 標準ライブラリと Git を使い、一時リポジトリで通常動作、変更前の競合検出、壊れたリンクを含む意図しない書き込みの拒否を検証する。
