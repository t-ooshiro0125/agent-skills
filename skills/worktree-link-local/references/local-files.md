# 共有対象と Git 除外設定

## 共有対象の指定

共有対象は依頼時に指定するほか、対象リポジトリの文書に記載できる。チーム共通の指定は `AGENTS.md` や開発規約、個人環境の指定はリポジトリ内の `AGENTS.override.md` に記載する。個人用の `AGENTS.override.md` は Git 共通ディレクトリの `info/exclude` に登録し、Git 管理対象にしない。

例えば、`AGENTS.override.md` に次のように記載する。共有するパスは対象リポジトリのルートを基準に示す。

```markdown
## worktree で共有するローカルファイル

パスはリポジトリのルートを基準とする。

- `<共有するパス>`：<用途・共有が必要な理由>
```

文書に指定があれば、依頼のたびに共有対象を列挙する必要はない。スキルが指定を読み、補助スクリプトの `--link` に渡す。補助スクリプト自体は文書を読み取らない。指定がない場合も除外対象を一括共有せず、必要性と影響を確認して対象を選ぶ。これらは共有対象の記載方法の案内であり、worktree の準備依頼だけで、規約や個人用の文書を自動作成・変更しない。

補助スクリプトがリンクできるのは、共有元で Git の除外対象になっているパスだけ。指定があっても、Git 管理対象や共有先の既存ファイルを上書きしない保護条件は維持する。ユーザー共通のスキル保存先はリンク不要とする。

リンク経由の編集は共有元にも反映され、共有元の移動・削除でリンクが切れるため、元フォルダはそのまま残す。リンクによる相互影響が不適切な場合や、除外されていない未追跡ファイルには、コピーや worktree ごとの個別管理を代替案として提示する。コピーは自動では実行せず、明示的に依頼された場合だけ別の操作として扱う。その場合も既存ファイルを上書きしない。

## リンクと Git 除外設定

補助スクリプトは、Git 共通ディレクトリ内の `info/exclude` に、リンクそのものに一致する除外パターンを追加する。末尾が `/` のディレクトリ除外パターンだけでは、シンボリックリンク自体を除外できないため。この設定は同じリポジトリのすべての worktree に適用される。
