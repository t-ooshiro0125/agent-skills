# Worktree Start

## 対象と前提

既存 worktree の起動を依頼された場合に使う。対象の絶対パス、ブランチ、指示ファイルと開発手順を確認し、利用先が定義する環境確認・依存関係確認・起動方法を使う。専用スキルから渡された確認コマンドと分離条件も引き継ぐ。

起動方法や接続先を特定できない場合は、利用先のスクリプトと設定を調べる。接続情報や認証情報を表示せず、残る判断に必要な情報だけ確認する。

## 起動手順

1. 対象の作業状態と、起動に必要な設定・生成先・依存関係を確認する。設定を共有している場合は、ポート、ジョブ、DB や cache の接続先などが並行稼働に適した状態か確認する。確認のために DB 接続やデータ変更を自動で行わない。
2. 起動依頼には、起動に必要な依存関係の確認と導入を含める。利用先のツールと lockfile を保持する方法に従い、関係のない更新を行わない。OS 全体のツール導入や migration は自動で行わず、必要な場合は利用先の規約と依頼範囲を確認する。
3. 前提がすべて満たされたら、対象 worktree から利用先の起動コマンドを実行する。統一起動スクリプトが指定されていれば、個々のサービスを別に起動しない。
4. 対象のプロセス、session、log や利用先の確認方法で起動結果を確かめる。コマンドの成功や対話画面への接続失敗だけで、起動成否を決めない。

## 失敗時と出力

失敗した起動コマンドをそのまま繰り返す前に、対象の session やプロセスが残っているか調べる。再試行が必要なら利用先の復旧手順に従い、対象 worktree のものだけを操作する。他の worktree のプロセスや共有サーバー全体を終了しない。

対象 worktree、実施した確認・依存関係の導入、起動結果と残った準備を簡潔に示す。失敗した場合は途中の状態と理由を示し、生成物や作業差分を自動で巻き戻さない。
