# Write PR Text

## 目的と対象

レビューする人が変更の目的、最終的な挙動、検証結果を判断できる PR タイトルと本文を作る。利用先の指示ファイル、PR テンプレート、文面の言語と規約に従う。専用スキルから呼ぶ場合は、そこで指定された基準ブランチ、チケット情報、書式を引き継ぐ。

## 差分の確認

1. 対象リポジトリと現在のブランチ、HEAD、作業状態を確認する。ユーザーが指定したブランチ・比較範囲を優先し、指定がなければ利用先の規約に従う。対象ブランチが指定でも規約でも決まらない場合は、現在の HEAD を対象にする。確定した対象の先端コミットを `target_commit` として記録する。基準ブランチが決まらなければ PR の設定やリモートの既定ブランチを調べ、判断できない場合だけ確認する。`main`、`master`、`develop` や `origin` を固定しない。
2. 利用先に指定された方法でチケット・要件を読む。取得できない情報は推測で補わず、利用先のフォールバック規約に従う。チケットを必須にする規約がなければ、チケットがないことだけで中断しない。
3. リモートの基準ブランチを使う場合は、指定されたリモートと ref を fetch して最新の参照を確認する。作業ブランチの切り替え、pull、merge は行わない。更新に失敗した場合は古い参照を最新と扱わず、理由と必要な確認を示す。
4. 通常は基準ブランチと `target_commit` の merge-base から、`target_commit` までのコミット済み差分を確認する。commit log、diff stat、変更パスも同じ対象コミットで確認し、本文に記載する挙動の根拠となる差分・関連実装を読む。明示された別の比較方法があればそれに従う。未コミット変更は通常の PR 差分に混ぜず、含める依頼がある場合は未コミットであることを区別する。

## 文面の作成

- タイトルと冒頭で、具体的な問題と変更後の挙動を伝える。詳細は差分の規模とレビュー上の判断に必要な量に合わせる。
- 経緯や会話を再現せず、最終的な変更内容を書く。採用しなかった案は、現在の選択を判断するために必要な場合だけ記載する。
- テンプレートの構成とチェック項目を維持する。検証済みと未実施を区別し、テストの存在を実行成功と扱わない。チェック欄は利用先の規約に従い、根拠なく埋めない。
- チケットの ID や URL は取得した値を使う。取得失敗時の URL 組み立てやタイトル形式は、利用先に定義されている場合だけ使う。
- 文面生成だけの依頼では、追加のテスト実行を必須にせず、確認できた実行結果だけ記載する。

## 出力と実行範囲

正常時は、そのまま利用できる PR タイトルと本文だけを出力する。利用先に出力形式の指定がなければ、タイトルと本文をそれぞれコピーできる形で示す。基準や対象を確定できない場合は、その理由と必要な確認を示す。

PR の作成・編集・投稿、チケットの更新、commit、push は行わない。外部に書き込む別の依頼がある場合も、このスキルの文面生成とは別の操作として扱う。
